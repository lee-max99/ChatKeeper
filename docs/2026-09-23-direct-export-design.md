## 最终设计
1. 用当前已登录会话直接请求同源 `/api/auth/session` 和 `/backend-api/conversation/{id}`。令牌仅在当前页面隔离脚本的请求函数内使用，不返回、不保存、不打印、不发往其他域名。无新增权限。
2. 按 mapping 的 parent 关系恢复当前选中分支的全部消息。对可见消息 ID 与 current_node 路径交叉验证；明显冲突、树断裂、循环、正在生成时停止。不能读取完整结构则报错，绝不悄悄导出 DOM 片段。
3. 保留原始 Markdown；HTML 使用本地 Markdown 解析和安全的 MathML 公式渲染。隐藏系统/内部分析/工具指令不作为聊天正文；图片/附件保留名称、合法链接和说明。
4. 弹窗只显示标题、格式卡片、进度状态和一个导出按钮；运行时可以取消。删除自动补采开关、开始/继续采集按钮、范围折叠面板及相关术语。出错使用可操作文案。
5. 内容脚本保存任务状态，关闭弹窗后读取继续；重开取回结果再导出。每次主动导出重新检查/读取，避免用过时缓存。任务与固定对话 URL 绑定。
6. 保留 0.2 的紫色品牌和离线目录/搜索；增强搜索结果的提问上下文与关键词高亮。图片/附件说明仅在实际存在时出现，正常文本文件不插入冗余流程警告。

## 验证顺序
- 单元测试先验证 mapping 分支顺序、1000 条未渲染消息、残缺/循环数据、权限/超时错误和取消。
- 替换内容脚本消息任务测试；不再将滚动代码放入构建。
- 浏览器用同源 API 仿真返回 1000 条消息、页面仅渲染 4 条，验证导出1000条且滚动次数为0、位置不变。验证导出期间弹窗关闭重开、鉴权失败不下载、生成保护、恶意正文净化和离线阅读。
- 更新文档、版本及安装包。真实账号/工作区接口适配需明确列为未验证；不能把仿真测试说成真实账号测试。
