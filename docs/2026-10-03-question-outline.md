# ChatKeeper 0.5.0 页面提问目录

用户确认将页面浮窗改为提问目录，导出保留在工具栏。目录展示当前页面已加载的提问，点击定位对应问答。保留小按钮、300px 白紫面板、拖动收起、位置记忆和切换会话时保持展开。

question-outline.ts 提取有用户角色、显式用户 turn、用户气泡或用户无障碍标题的提问；不要求消息 ID。排除回答、隐藏分支、侧栏及输入表单，按节点顺序保留重复提问。文本作为 textContent 展示，附件提问优先使用可读名称。目标滚动使用 scrollIntoView，临时提供 80px 顶栏偏移并还原原样式；遵循减少动画设置。

floating.ts 使用页面内容变更更新列表，通过捕获滚动事件标记当前问答。收起或关闭时跳过定时目录采集；内容不变时保留按钮，新增/编辑时恢复对应问题的焦点和目录滚动位置。会话切换时暂时清空目录，排除未变化的旧提问节点，允许节点文字或可用消息标识改变后重新纳入，避免输入区或回答状态变化带回旧目录。此机制仅用于目录，不改变 API 导出的宽松识别策略。

目录只读取已加载的页面内容，不主动补载旧历史或调用聊天接口；未加载内容在页面加载后加入。标题、问题文本和节点只保存在当前页面内存中。扩展存储仍仅包含显示开关、位置和导出格式。

独立审查补充了无属性用户标题结构在节点复用时恢复、同节点 A→B→A 返回会话的检查。旧节点一旦被接受为新会话提问，就淘汰它更早的快照，防止历史版本成为永久排除项。两种情况均先在浏览器复现失败再修复。审查报告的导航和焦点问题全部解决；最终 60 项单元检查、13 项目录场景、原完整导出与离线阅读检查通过。

新增单元检查和仿真浏览器检查先复现缺失目录、回答引用误收、导航显示旧提问、无关变动解除等待、新增/编辑丢失键盘焦点，再逐项修复。浏览器检查包含实际嵌套聊天容器滚动、阅读位置高亮、异步导航、节点身份复用、无接口请求、拖动/位置恢复/收起、窄屏及严格 CSP。原完整 API 导出和离线 HTML 检查继续运行。报告在 artifacts/floating-report.json、artifacts/browser-report.json。

仿真页面测试不等同于真实登录后的 ChatGPT 或 Edge 验证；网页结构变化仍可能需要更新目录识别。

## 后续 v0.5.1

用户反馈聊天已经显示、工具栏可以下载，但目录为零，因此在展开且无法采集任何提问时复用当前会话完整记录读取。每个网址自动尝试一次，提供手动重试，不为已识别目录或收起入口自动请求接口。普通 `/c/` 与项目 `/g/.../c/` 会话统一使用既有网址解析。保存记录仅留在内存中；导航时清空，回调再次核对网址。

浮窗保留目录主体，底部增加格式选择、下载和仅在工作时显示的状态及取消按钮。下载重新准备当前路径记录，发送文件前检查页面和任务身份，不把目录片段当作完整记录。工具栏原导出能力保留。

回退目录按导出消息身份查询源节点别名，避免 system、隐藏或工具节点造成索引错位。先绑定可靠 ID；同文提问只有在页面目标数量一致时按顺序定位。未明确标记为用户且文字也出现在保存回答中的目标保持未定位，避免跳到回答引用段落。上述定位判据不阻拦目录列出或下载。补充失败测试后逐项修复，并同步更新 README、CHANGELOG 和隐私说明。
