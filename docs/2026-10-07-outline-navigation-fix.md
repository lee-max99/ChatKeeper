# 目录定位误判排查与修复

提示来自目录点击时的定位失败，不是 API 读取或导出失败。完整保存目录含未在 DOM 中出现的历史项，也可能存在同文重复提问的定位歧义。

本地复现确认：保存的两行用户消息与页面 `第一行<br>第二行`，或两个相邻 div 排版，虽然 collectQuestions 已识别为“第一行 第二行”，savedQuestionOutline 仅比较原始 textContent，导致 target=null。修复仅增加已识别用户消息清理正文的匹配，保留原始 textContent 和原来的 ID 优先、重复数量校验、回答引用排除。没有加入自动滚动加载或顺序猜测。

两个回归断言先失败（target=null），修复后通过；增加相邻行内格式无空格的保留检查。仿真浏览器检查完整保存目录中多行提问实际跳转、缺失历史提示及完整导出。提示改为“暂时无法定位该提问，请在聊天页加载后重试。下载不受影响。”，不再声称所有失败均因尚未加载。

实际遇到问题的用户是否已加载目标消息尚不明确，不能把本地复现结论当作所有用户的唯一根因。

验证：89 项单元测试通过（maxWorkers=2），构建和类型检查通过，28 个浮窗仿真浏览器场景通过、无页面错误。加载多行提问实际滚动至目标节点，未加载历史项仍可完整下载。实际用户登录页面尚未验证。初次并发运行出现无关 session 5 秒超时；降低并发后全套通过。浮窗既有读取中下载场景在负载下 1 秒响应已先完成，扩大该仿真接口延时至 3 秒以保留重叠窗口，原单次准备断言仍保留并通过。

独立复核发现清理正文中的插入空格可能抢占另一提问的精确原始文字匹配。追加两个保存顺序的回归检查，先复现错误定位，再限定清理匹配仅用于原始文字不匹配任何保存提问的候选，89 项全套检查通过。修复后的最终构建和浮窗检查重新执行，安装包需以最终构建重新生成。

最终构建后的 28 个浮窗场景再次全部通过、无页面错误。ChatKeeper-0.6.1.zip 已重新生成，14 个文件均与最终 dist 的 SHA-256 一致。

发布 v0.6.2 前复核补充：带编辑按钮和隐藏标题的行内格式提问仍可能被插入空格的清理正文抢占。新增两个保存顺序的检查，先观察到错误绑定，再以移除控件后的连续正文保留精确匹配，95 项单元测试及构建通过。
