# 图片与交互内容导出兼容 · 0.6.6

用户反馈图片和 Intelligent UI 在导出后出现乱码。初次处理时没有具体失败样本；后续用户提供了新导出 HTML 的截图，显示 `box` / `text` / `row` 等布局标签和误识别的缩进代码块。现已按截图重建样例，原始保存记录及 HTML 文件尚未提供，不能断言覆盖所有新版组件。

## 原因

保存记录中的字符串此前直接进入 Markdown / HTML 导出；包含私用字符框定的图片引用或组件标记时，内部标记、资源 ID 和载荷可能直接显示。结构化图片此前仅输出通用占位说明，丢失可用标题或链接。ChatGPT 内部图片地址也无法直接在离线文件中使用。

## 处理

- 仅转换 assistant 正文中代码以外的组件标记；保留用户文字、代码块与行内代码的原始内容。
- 引用优先使用记录内已有的标题、说明和 HTTP(S) 链接，没有公开链接时保留标题并提示查看原对话。
- 图片组保留可识别的检索词并明确其性质；实体保留可读名称。未知完整组件只提供说明，不导出内部 JSON 或执行脚本。
- 不完整标记只替换确定的前缀，保留后续原文；不猜测正文的结束位置。
- 保留媒体片段已有的文字，例如音频转写。内部图片 Markdown 地址转换为可读说明，不输出无法打开的图片链接。
- 所有元数据按文字转义；拒绝脚本、内部资源协议及带凭据的资源链接。不自动获取图片，不嵌入原文件。
- 截图补充：初次处理仅识别私用字符标记，类似 JSX 的标签会直接通过，之后被 Markdown 渲染器转义显示；其中缩进的 `text` 还会被当作代码。新增保守的标签读取器，仅将代码以外、带布局属性且正确闭合的 `box` 布局转为段落，保留正文及已识别的方向箭头；清除该布局中的缩进，不读取或执行组件属性表达式。
- 明确的围栏代码、行内代码、组件外的缩进代码及用户原文保持不变。孤立标签、未闭合或错位标签保持原文，避免猜测边界后删除正文。此转换不还原原始布局或交互。

## 验证与边界

新增单元回归覆盖图片引用、无公开 URL 的说明、内部资源地址、实体、组件降级、恶意元数据、媒体转写，以及含转义反引号或 Markdown 载荷的代码边界。浏览器场景实际下载 Markdown / HTML，离线打开 HTML 检查可读文字、链接与无远程请求。

截图回归样例位于 `tests/fixtures/ui-markup.txt`。新增检查覆盖截图中的完整流程、缩进说明、含尖括号与 JSX 表达式的属性、代码示例保护及不完整布局；3 项针对缺口的测试修复前失败，修复后通过。浏览器检查从扩展实际下载两种格式，检查离线 HTML 中的段落、箭头、正文及无远程请求。

复核补充两项缩进组件内的行内代码回归：反引号包裹的 `icon` 不应转换成箭头，字面量 `box` 不应破坏外层标签配对。两项均先复现失败，再补齐该区域的行内代码范围识别。

测试使用构造的保存记录（含截图转写样例）和隔离浏览器环境，未使用用户登录会话或原始失败记录。无法还原的组件会提示回原对话查看；这不是 Intelligent UI 的完整离线运行支持，也不保证所有未来组件格式均可识别。

[OpenAI Intelligent UI 说明](https://help.openai.com/en/articles/20001598-intelligent-ui-in-chatgpt)确认其包含图形、表单、按钮等交互内容，但未提供导出协议。解析规则来自本项目针对已知标记模式的兼容处理，不能视为官方格式契约。
