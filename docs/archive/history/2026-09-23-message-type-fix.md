# 0.3.1 消息类型过滤修复

> 历史开发记录：本文描述当时的设计或验证结果，可能与当前版本不同。当前行为以根目录 README 和源码为准。

用户截图中反复出现“非文本消息（thoughts）”和“非文本消息（reasoning_recap）”。

根因：原过滤只看角色、channel、隐藏标记与 recipient。上述 content_type 在缺少 channel / 隐藏标记时进入 messageText；无普通 parts / text 时生成类型占位，有 text 时则可能误输出辅助内容。

修复：在正文转换前按准确的 content_type 排除 thoughts、reasoning_recap。仍沿完整 parent 链解析当前分支，不能删除节点后再断链。保留 commentary / final 正文，不根据消息文本关键词过滤；图片、附件和未知特殊内容的提示继续保留。

回归测试先复现失败，再确认通过。测试覆盖两种辅助类型、存在 text 的辅助类型、辅助记录位于 current_node、前后正文连续、替代分支排除、正文中合法类型名、Markdown / HTML 输出及消息计数。浏览器接口仿真也加入两种辅助节点，原有 4 条正文计数断言保持不变。

用户提供的私有对话链接仅返回未登录页面，未访问其真实接口数据。本修复基于截图和本地可复现的数据路径，不声称已经逐条核对其账号中的对话。
