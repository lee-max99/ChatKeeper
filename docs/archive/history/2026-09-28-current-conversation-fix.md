# ChatKeeper 0.3.2 当前会话识别修复

> 历史开发记录：本文描述当时的设计或验证结果，可能与当前版本不同。当前行为以根目录 README 和源码为准。

日期：2026-09-28

用户反馈：刷新后持续出现“当前分支与保存记录尚未同步”；只希望保存当前页面正在显示的一条对话，包含未加载历史，不要旧回答或其他版本。

## 根因范围

未取得用户实际报错页面的 DOM / 接口数据，不能确认现场唯一根因。通过新增回归测试，在旧代码复现了重复 DOM 消息标识、节点 ID / 消息 ID 不同、辅助记录形成多个叶节点，以及导出前校验误把已过滤的辅助记录当作内容变化的问题。另验证了无关默认指针损坏和短暂保存延迟。

## 修复

- 消息 ID 按逻辑消息去重，保留顺序与不同 ID 的重复文本。
- 仅接受接口明确提供的节点 key、node.id、message.id 别名，不猜测 ID 后缀、不按相似文本匹配。
- 候选路径按实际导出的消息 ID 序列比较，辅助记录不会导致相同正文被误判为不同对话。
- 导出前使用原选定路径的 ID 别名校验。保留 ID 验证信息，辅助正文仍被过滤，不进入导出文件。
- 页面有明确证据时允许从损坏的无关默认指针恢复；真实多解、跨路径和顺序冲突仍拒绝。
- 缺失保存消息时最多重试两次，复用本次会话凭据，不持久化令牌；取消和原 45 秒时限继续生效。
- 页面没有可识别消息时，不直接导出 API 默认选择。
- 错误提示区分未对应消息、顺序冲突和需要看到末尾回答，避免统一称为“分支未同步”。

## 验证

45 项单元测试通过，类型检查与生产构建通过。

Chromium 仿真集成测试通过：接口默认旧回答、页面当前回答、重复包装节点、node/message ID 不同、辅助叶节点均参与同一个实际下载场景；确认只导出当前选定的 4 条消息，没有旧回答或辅助占位内容。原 1000 消息无滚动导出、离线 HTML、取消、登录失败、接口错误、生成与站点保护继续通过。

浏览器报告：artifacts/browser-report.json。实际用户页面与 Edge 尚未验证，不能以仿真测试声称所有 ChatGPT 页面均兼容。
