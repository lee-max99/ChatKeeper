# ChatKeeper 0.3.4 导出优先

> 历史开发记录：本文描述当时的设计或验证结果，可能与当前版本不同。当前行为以根目录 README 和源码为准。

用户在 0.3.3 仍遇到页面内容已显示但没有可识别消息的阻拦，并明确要求不使用过于严格的判据，目的为导出聊天记录。

取消 CK_PREPARE 的非空页面 ID 门槛；页面识别不完整时返回空辅助信息。CK_CHECK 只检查网址和生成状态，不检查 DOM ID 是否仍与结果一致。

完整记录仍按当前网址对应的会话 ID 获取。页面 ID 与记录能够对应且路径唯一时保留选中的回答。页面 ID 缺失、未知、冲突或多解时使用记录的 current_node 路径。未知 ID 先短暂重试两次，第三次使用已有保存记录。只导出一条路径，不合并所有叶节点，不跨会话。无法识别页面时无法保证保存的回答版本与用户刚切换的替代回答一致，文件附保存版本说明。

保留登录、请求错误、取消、45 秒时限、正在生成、网址变化、保存路径损坏检查。这些检查防止空文件、错误会话或残缺数据，不再依赖页面属性识别成功。

52 项单元测试覆盖新的降级策略、原准确选择、完整 1000 消息、权限和取消。浏览器仿真增加内容已显示但无任何消息属性时的 Markdown / HTML 实际下载，以及未知页面 ID 重试后的完整导出。构建和浏览器报告见 artifacts/browser-report.json。

未获取真实报错页面的 DOM 和保存接口响应，本次验证针对已确认导致阻拦的代码路径与仿真下载。
