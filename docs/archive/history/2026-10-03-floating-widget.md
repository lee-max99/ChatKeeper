# ChatKeeper 0.4.0 常驻浮窗

用户确认的交互：页面内常驻浮窗，首次打开默认显示小按钮；点击展开后点击聊天区域不关闭；切换会话继续展开；支持拖动和收起。UI 约 300px，白色、轻阴影、紫色点缀，保留标题、格式和导出按钮。用户在讨论结束后明确要求开始实现。

自动页面脚本仅匹配 https://chatgpt.com/*，使用 Shadow DOM 隔离网站样式。按钮 36px，浮窗 300px，窄屏使用可视宽度限制和位置边界。位置、格式和显示开关保存在 chrome.storage.local，聊天记录和令牌仍只在内存中。

浮窗与原工具栏弹窗通过同一份页面任务共享 API 读取、取消和完成校验。网页内容脚本获得下载入口，后台验证同一扩展、ChatGPT 顶层页面来源以及文件大小和名称。切换会话会取消旧准备、更新标题并保持展开。刷新页面默认收起。

生产构建补上 esbuild 的 ?raw 文本加载，确保离线 HTML 阅读脚本作为字符串嵌入，不在网页中直接执行。保持 0.3.4 的导出优先策略，不恢复页面 ID 的硬性门槛。

验证包含真实扩展在仿真页面中的浮钮自动加载、外部点击不关闭、MD/HTML 实际下载、会话切换、拖动与位置恢复、格式恢复、关闭开关、窄屏、取消、准备期间切换和严格页面 CSP。原 1000 消息及离线 HTML 浏览器用例继续执行。报告位于 artifacts/browser-report.json 和 artifacts/floating-report.json；实际登录后的 ChatGPT 页面及 Edge 尚未实测。

独立代码审查发现收起/关闭时仍有消息扫描、拖动后键盘展开被拦两处问题。新增浏览器回归检查分别复现，修复后通过；复查确认两处均已解决。

0.4.1 补充修复工具栏准备任务与浮窗导航之间的衔接：URL 变化时检查共享任务的网址，只取消旧会话的任务，不再仅看浮窗自身的 busy 标记。取消立即释放 controller；异步完成、失败和清理只允许修改自身仍在运行的任务。单元检查覆盖取消后立即准备和旧请求晚结束，浏览器检查覆盖工具栏准备后切换、直接用浮窗下载新会话。复查发现无条件取消也会误取消先于浮窗更新启动的新会话任务，增加反向顺序检查复现失败后改为按任务网址失效。上述检查均通过后才打包。
