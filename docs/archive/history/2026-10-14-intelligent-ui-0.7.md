# Intelligent UI 通用静态导出 · 0.7.0

## 本次反馈与原因

用户第二张截图显示独立 `text`、`row`、`title` 以及 `Chart content={{...}}` 仍以源码形式出现在新导出的 HTML 中。0.6.6 的入口只检查 `box`，标签处理也只认识少量布局组件，导致独立组件与结构化图表被直接传给 Markdown 渲染器。用户要求同时考虑所有组件，不能继续只针对截图增补标签名单。

## 统一处理方式

`src/ui-markup.ts` 读取完整标签、属性和配对关系，再递归处理组件树；自定义名称统一进入转换，不要求外层 `box`。`src/ui-literal.ts` 只读取字符串、有限数值、布尔值、null、对象与数组，不执行 JavaScript。`src/ui-data.ts` 将结构化数据转成表格或分段说明。Markdown 和 HTML 共用此结果。

| 类型 | 静态导出行为 |
| --- | --- |
| 容器、文字、标题、指标 | 保留正文、名称、值、单位、说明及段落顺序 |
| 图表 | 可识别的横轴与多序列数据转为数据表，保留零值、前后缀、标题和脚注 |
| 表格 | 支持结构化列/行及组件内的 table/tr/th/td 结构 |
| 列表、标签页 | 保留所有项目、标签名称和各页正文，不只导出活动页 |
| 按钮、链接 | 保留标签；可用 HTTP(S) 地址转为链接，按钮注明交互需在原对话使用 |
| 输入、选择、滑块、勾选控件 | 保留保存记录中的标签、值、选项、范围和已提供的勾选状态 |
| 图片、音频、视频 | 保留名称、说明和安全链接，不嵌入或自动加载原文件 |
| 未知组件 | 不依赖名称白名单，展开正文和可读静态数据；无可用内容时给出明确提示 |
| 明确的代码示例、用户文字 | 保持原文，不当作组件执行或转换 |
| 未闭合、边界不确定的标签 | 保留原文，避免误删后续正文 |

## 边界

这是一套静态内容导出机制，不是 ChatGPT 原生编译器的复制。组件脚本、动态计算、事件回调、游戏、表单提交及原始视觉布局不能靠静态保存记录完整复现；尚未保存的交互状态也不可推断。无法识别的数据结构会转成可读属性与列表，而不会声称已正确还原为原图表。

[官方产品说明](https://openai.com/index/gpt-6-for-everyone/)描述了组件库、编译器及图形、表单、按钮等体验，但本次查阅到的公开页面没有完整组件清单、属性 schema 或离线导出协议。因此“统一处理未知组件”不等于保证任意当前或未来组件都能完整还原。解析依据是用户截图及本项目的兼容样例。

## 验证

`tests/fixtures/intelligent-ui.txt` 按第二张截图转写，检查 L1/L3/R1 的 8.42% / 8.86% / 9.23%、脚注、CRC 数值和前后正文。`tests/fixtures/ui-components.txt` 覆盖未知容器与数据、表格、标签页、列表、链接、媒体和静态控件，并保留一段真实代码示例。

单元测试先复现新增兼容缺口，再检查静态字面量、错误边界、代码保护与恶意属性。浏览器测试实际下载 Markdown / HTML、离线打开、核对表格及正文，检查没有组件脚本和远程请求。所有样例使用构造的保存记录，不代表用户登录环境或所有未公开组件的实测结果。

2026-10-14 验证结果：160 项单元测试、18 个导出浏览器场景、31 个浮窗场景通过，类型检查与构建通过。人工检查截图样例和组件合集的离线导出截图，正文和数值可读，明确的代码示例保持原样。`artifacts/ChatKeeper-0.7.0.zip` 的根目录版本为 0.7.0，包内 11 个文件与 `dist` 的 SHA-256 校验一致。
