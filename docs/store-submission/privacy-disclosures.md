# 隐私后台填写参考

本文件是填写说明，不是已完成的后台申报。应对照提交当天后台对“收集”“处理”“传输”的定义填写，保持与 docs/privacy.md 和代码一致，不能因为本地处理就笼统承诺“不读取任何数据”。

## 实际处理的数据

| 数据 | 用途及保留 | 开发者是否接收 |
| --- | --- | --- |
| 网站内容：聊天正文、标题、提问、消息标识、附件名称/链接 | 当前会话目录、导航及导出；页面内存与用户下载的文件 | 否 |
| 身份验证信息：当前 ChatGPT 会话的临时访问令牌 | 仅在页面内存中用于同源读取当前会话，不保存到文件或扩展设置 | 否 |
| 当前页面网址、滚动位置、目录点击/选择状态 | 更新当前会话、定位问答；页面内存，导出文件含来源网址 | 否 |
| 浮钮开关、位置和格式偏好 | 浏览器本地扩展设置，可随卸载移除 | 否 |

聊天文本本身可能含姓名、邮件、健康、财务等敏感信息；扩展不专门提取或分析这些类别，但不能宣称导出文件绝不含个人信息。扩展不跟踪跨站浏览历史，不读取其他扩展下载记录，不销售数据，不用于广告，不提供数据经纪服务。

## Chrome Privacy practices

- 单一用途：导航并保存当前打开的 ChatGPT 会话。
- 按 review-notes.md 填写每项权限理由；站点访问只限 ChatGPT。
- 关于远程代码：不使用远程可执行代码。读取聊天数据不是下载脚本；库和阅读器脚本均随包提供。
- 数据类别：重点核对 Website content、Authentication information，以及 Web history / User activity 的现场定义与本表处理范围。若后台将本地处理也计入 collected/handled，应如实勾选对应类别；不要把“无开发者上传”当作自动全不勾选的理由。若定义明确排除仅本地处理，按定义填写并保留本文件解释。
- 有限使用声明已经加入隐私说明。确认实际行为与后台的用途限制承诺一致后，再由发布者完成相关认证勾选。
- 隐私政策 URL：必须使用公开可访问、无需登录的地址。不能填写本地文件路径。

## Edge Privacy

按后台所问的是访问、处理还是开发者收集作答，参考上述数据流；不要将读取聊天内容的扩展描述为“不访问用户数据”。上传同一份公开隐私政策。若需要发布者联系邮箱，填你真实可收信的邮箱，本材料未代填。
