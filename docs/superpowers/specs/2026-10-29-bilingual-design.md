# ChatKeeper 中英文支持设计（待确认）

日期：2026-10-29。基线：根目录工程 v0.7.5，HEAD b46b39e。本文是方案，不表示英文功能已经实现。

## 已确认的目标

用户选择同一个插件支持简体中文和英文，默认跟随浏览器，也可以手动切换。不制作另一份独立英文安装包。保留简洁的现有界面、当前会话单一路径、部分问答导出、目录定位和聊天原图保存；不恢复 PNG 长图导出。

聊天标题、提问、回答、代码、附件名称、图表标签等原始内容不做机器翻译。需要翻译的是插件及导出器自己生成的界面、元数据、提示和降级说明。

## 当前工程与影响范围

| 部分 | 当前实现 | 本次影响 |
| --- | --- | --- |
| 安装与构建 | MV3，Chrome/Edge 109+；Vite 构建 popup，esbuild 构建 content/background | 同一安装包加入语言目录，不增加权限 |
| 工具栏弹窗 | popup.html、src/popup.ts、src/popup.css | 静态文字、运行状态、语言设置 |
| 页面浮窗 | src/floating.ts、floating-selection.ts、floating-download.ts、floating-style.ts | 目录、搜索、选择范围、定位反馈、下载状态及无障碍标签 |
| 页面桥接 | src/content.ts、page-info.ts | 消息校验、错误传递与语言更新 |
| 会话读取 | src/conversation-api.ts、message-identity.ts | 仍按当前路径读取，生成说明与缓存需支持语言变化 |
| 导出范围 | src/conversation-selection.ts | 所选问答的校验不能因切换语言而失效 |
| 内容转换 | rich-content.ts、ui-*、markdown-renderer.ts | 附件/未知组件等生成说明需要本地化，内容及识别规则保持原意 |
| 原图保存 | image-assets.ts、image-fetch.ts | 图片进度、失败数量和生成的默认名称 |
| 文件保存 | background.ts、download-client.ts | 下载失败、待确认与成功结果需要独立状态，不能依赖中文文本 |
| 离线文件 | exporters.ts、reader.js、document-style.ts | HTML 阅读器、Markdown 元数据、角色名、图片保存、复制反馈 |
| 文档与发布 | README、docs/privacy.md、Edge 商店资料、public/manifest.json | 英文帮助、隐私说明和商店文案；本地打包，不自动上架 |

主链路：弹窗或浮窗发起 → content 读取当前会话并校验 → API 选择单条消息路径 → 确定完整/所选问答 → 读取此范围内的原图 → Markdown/HTML 转换与净化 → background 创建下载 → 查询下载记录确认结果。

目录定位是另一条链路：识别页面提问，必要时用保存记录补齐目录；用户点击未挂载的提问时，滚动触发 ChatGPT 加载再定位。导出本身不通过滚动采集。本次不能混淆这两条链路。

## 方案取舍

1. **已选：一个插件、自动语言加手动切换。** 共用导出引擎和安装包，中英文功能保持一致，避免维护两个分支。
2. **独立英文包。** 界面可固定英文，但会重复维护、测试和发布，用户不选择此方案。
3. **只跟随浏览器。** 修改较少，但无法在中文浏览器中使用英文界面，不满足已确认的手动切换要求。

## 语言规则与入口

- 设置提供 `跟随浏览器 / 简体中文 / English` 三项；首次和没有有效设置时为跟随浏览器。
- 自动模式读取浏览器界面语言，不读取 ChatGPT 页面语言。中文语言变体使用简体中文，其他语言使用英文；这是仅支持两种语言时的回退选择，不宣称支持繁体或其他语言。
- 在弹窗现有偏好区增加一行紧凑的语言选择，不给浮窗再加一套设置面板。
- 手动选择写入现有 chrome.storage.local，跨标签页同步。只保存语言偏好，不保存聊天正文、标题、令牌或翻译历史。
- 切换后更新已打开弹窗和浮窗的文字，不刷新 ChatGPT，不清空勾选、搜索词或已有目录，不重新读取会话接口。
- 扩展管理页的描述和浏览器工具栏提示使用浏览器自身语言；插件内的手动设置不改变浏览器管理页的语言。
- 英文采用简洁文案，例如 `Questions`、`Select Q&A`、`Export all`、`Export selected`、`Saved`；不用逐字直译堆长句。

## 实现边界与架构建议

### 统一词条

使用标准 `public/_locales/en/messages.json` 和 `public/_locales/zh_CN/messages.json`，为 manifest 的描述和工具栏提示设置 `__MSG_…__` 引用，设置 default_locale；默认回退语言建议为英文。品牌名 ChatKeeper 不变。

新增轻量且有类型约束的本地化入口，统一处理词条、参数、数量、初始语言和变更订阅。插件内的词条查找支持手动选择，不只调用跟随浏览器的 getMessage。两个语言包的键和参数必须一致。无需新增翻译服务、远程请求、框架或扩展权限。

### 状态与文案分离

当前存在以下依赖中文语义的逻辑：

- download-client.ts 用“已保存：”前缀和“张图片未能保存”正则拼接结果；
- floating-download.ts 用“等待保存…”决定能否取消；
- floating.ts 用“回答还在生成”判断目录刷新重试；
- image-assets.ts 用“图片…未嵌入”匹配并替换警告。

这些逻辑改用阶段、结果状态、错误/警告标识和数值参数；显示时才取对应语言词条。已生成的普通文本不再反向驱动业务判断。浏览器原生错误仍按现有连接/取消/下载状态归类，不将一段中文全文搜索替换为英文。

### 缓存、选择与导出语言

- 目录缓存里目前已经混入生成的说明文字。保留当前已选路径的原始消息素材或等价的语言无关描述，仅在页面内存中重建目标语言说明；不为了切换语言请求整个会话，也不长期缓存其他分支。
- 所选提问的身份和编辑检测依据稳定 ID 与原始内容，不能将本地化的附件默认名或生成说明变化当作用户编辑。
- question-outline.ts 的目录指纹也必须保持语言无关；不能因把默认“图片”标签改为 Image 而误判会话变化，触发额外接口读取或丢掉原来的定位目标。
- 每次导出开始时固定文档语言。即使另一标签页更改设置，也不在同一文件里混用两种系统语言。
- Markdown 的来源、时间、用户角色和系统提示跟随导出语言；原始标题、正文、代码、链接和图片内容不变。
- HTML 的 lang、日期显示、目录、搜索、复制、保存图片及其运行时反馈使用导出时固定的语言。其词条随文件一起保存，不依赖 chrome API、扩展安装、浏览器联网或外部资源。
- 本次不向离线 HTML 再增加语言设置入口；新导出的文件使用当前插件语言，旧文件保留原样。

### 英文布局与辅助功能

保留 300px 弹窗/浮窗的视觉风格，必要时调整换行、最小宽度和按钮间距，避免 `Export selected`、数量和范围控件挤压。覆盖小屏、长标题、较大数量、选择/取消/失败状态。

同时翻译 aria-label、title、placeholder、状态播报与默认图片名称。原有中英文 ChatGPT DOM 角色识别正则是页面解析规则，不能当作普通中文文案删除或替换。

## 文档和版本

建议作为 v0.8.0 发布，因为增加了完整语言能力；沿用现有安装方式和设置，不恢复已撤回的 v0.7.6 PNG 方案。

提供 README.en.md、英文隐私说明和 Edge 英文商店介绍，中文文档补充语言设置使用方法。商店描述、运行界面和最终包能力一致。现有 2026-10-29 文档归档/清理、Edge 准备资料是独立改动，本次保留，不回退、不覆盖历史检查报告。

## 验收

1. 中文浏览器自动中文，英文及未支持语言浏览器自动英文；手动选择优先于自动，重开后保持。
2. 已打开浮窗随设置变化更新，不丢失已选问答/搜索/阅读位置，不重复读会话接口；页面切换仍按原规则重置选择。
3. 两种语言均能完整导出和导出两组不连续问答；正文不翻译，不混其他分支，不增加 PNG 入口。
4. 下载成功、取消、待确认、生成状态、登录失败和图片缺失数量在两种语言下正确，不依赖语言字符串决定结果。
5. 英文离线 HTML 断网可读、可搜索、可复制和保存原图；动态提示仍为英文；Markdown 的系统文字为英文，中文正文保持原样。
6. 中文现有测试继续通过；增加词条完整性、回退、切换、缓存/选择保留和英文文档测试。真实扩展浏览器场景覆盖两种语言、窄屏、离线阅读和保存结果。
7. 类型检查、构建和安装包校验通过；验证 manifest 的语言目录完整，无新增权限或远程代码。
